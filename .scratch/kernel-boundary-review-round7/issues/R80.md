> 2026-09-18 独立复审：本卡两个原反例的修复存在，但新 claim 尚未登记 RunHandle 的窗口仍被旧取消释放。

## 责任范围与证据

`crates/alva-hub-core/src/runtime.rs:1079–1123`。基线 `c8aca9c8`。静态确认，探针未取得执行结果，不记作动态复现。

两条确定性交错：

1. 旧 cancel clone live handle，已经保存 generation；进入 capabilities() gate。另一线程 abandon 旧轮并启动同 pid 新轮 Running；gate 返回 cancel=false。1079–1081 仍无条件 self.abandon，误将新轮 Failed、取消 token 并移除/abort 新 RunHandle。1097 的无 native id 分支同样未使用目标校验。
2. fallback 分支先获取 Completed/native-old snapshot，然后停在 capabilities() gate；此时同 pid 新轮启动。gate 返回 true 后 1119 附近另取 claim_seq，得到新轮 claim，却对旧 native id 调 cancel。Unsupported 后 abandon_targeted 使用新 claim，依然中止新轮。

## 有限验收

- 用能力查询 gate 固定第一种交错，旧 cancel 返回后新轮仍 Running、句柄可达、真实新轮取消仍有效。
- 用 restored session 和能力 gate 固定第二种交错，确认旧 native id 与目标 claim 来自同一快照；旧 Unsupported 不影响新轮。
- 所有因能力不支持、无 native id、Unsupported 导致的释放使用原目标身份；路由和 claim 必须一致获取，不能分开采样。
- 保留现有 R63 的迟到 Unsupported 正例与当前轮正常取消测试；不要以单线程无 await 为由忽略跨线程执行。
- 限定 hub-core 实现，遵守其 AGENTS；记录真实命令、结果与独立 commit。
