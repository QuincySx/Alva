# R77: HTTP Stop 的取消事实与 marker 必须绑定原 attempt

Priority: P1
Origin: R65
Status: open

## 责任范围与证据

`crates/alva-hub-server/src/main.rs:613–638`；必要的条件写入接口位于 `crates/alva-hub-desktop/src/store/turn.rs`。
审查基线 `c8aca9c8704cabdcd66655213cd4c4b998e4c65a`。本卡为静态确认，尚未执行动态复现。

A 运行 → Stop 捕获 A 的 hub 后 await cancel → A 完成 → 同 pid 的 B 开始 → A cancel 返回 Ok。
623 行 `record_attempt_cancelled(&id, ...)` 根据当前 session/branch 写取消，实际落到 B；633 行仅按 pid 插入 marker，637 行检查 active_hubs 是否存在，B 存在便不能识别迟到确认。
HubRuntime 内部保护旧 claim 并不能保护 server 层这些写入。

## 有限验收

- HTTP fake-engine 集成使用确定性 cancel gate 固定上述交错，必须在 A 的 cancel 已进入但未返回时结束 A、启动 B。
- B 不产生取消事实、不显示旧 Stop 的 stopping 状态、不产生旧 Stop 导致的 Interrupted，且仍可正常执行和自行 Stop。
- 取消事实、marker、结算绑定同一 turn/attempt；校验与写入避免 check-then-write 竞态。
- 保留 cancel Err、正常 Stop、terminal-before-ack 回归。不能用“A 已完成后才请求 Stop”代替本卡交错。
- 只改 server/产品持久化必要接口，不向 kernel/agent-core 添加产品概念。
- 记录测试命令、实际结果、实现 commit；更新适用分形文档。
