# R94: 适配器自身错误不得与成功 Completed.result 并存

Priority: P2
Axis: Spec
Status: done (2026-09-19，commit 36d44ec9)
Origin: R81/R82 / 多引擎适配器
Baseline: bae66d0f8aeebac36b4a57b84fa955489ae63f0d

## 责任范围与问题

crates/alva-engine-adapter-codex/src/adapter.rs:149–156,238–244,268；crates/alva-engine-adapter-pi/src/adapter.rs:131–138,187–193,208。

native_terminal_seen 之后，读取错误/取消路径设置 error_forwarded，却不设置 mapper.failed；最终 result 只看 mapper.failed 和 native_terminal_seen 等。因此正常原生终态之后、EOF 之前发生错误，输出 fatal Error 后仍携带成功答案。

## 证据

真实 execute 的 healthy 对照均成功；terminal→非法 UTF8 的 Codex/Pi 两个反例均 fatal=true、has_result=true。合并 probe exit101。

## 有限验收

两 adapter 均回归 terminal→读取错误与 terminal→cancel，确保终态一致。允许明确把原生终态视为已提交成功而忽略后续错误，或报 fatal 且 result=None；不允许两者混合。保持恰好一个 Completed、健康正文/usage保留、真正缺终态 EOF 仍失败。修 mapper外错误状态的统一结算，不只是过滤该UTF8文案。

先保留反例再修实现，每个逻辑改动单独提交；记录真实命令、结果和 commit。遵守根/目录 AGENTS、分形协议；不回退其他人的修改。反例来自当前真实 API，但假引擎/CLI 不代表真实服务端端到端已验收。
