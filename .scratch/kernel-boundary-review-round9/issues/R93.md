## 责任范围与问题

crates/alva-hub-core/src/runtime.rs:652–655,1253–1262,1353–1379。

R90 保住 pending_handoff/banner，但失败 native id 仍等 EOF 才恢复。fatal→EOF 窗口重试 prompt 有标记，却 resume 失败轮 native ID；等 EOF 后重试则 native=None，行为由尾流时序决定。既有 fatal_first_handoff_stream_preserves_context_for_retry 明确要求失败后 native 清空，新测试只检查 prompt 漏掉这项。

## 证据

实际运行 evidence/hub/handoff_native.rs：exit 101，retry marker count=1, retry native=Some("native-0"); expected None。

## 有限验收

在允许重试之前完成与 EOF 后相同的失败 handoff 身份恢复，或等待恢复再允许认领。gate 覆盖 fatal 后 EOF 前/后的两种时序；比较完整 RuntimeRequest 的 resume_session 与 prompt，banner恰好一次且失败 native 不被恢复使用；旧尾部不覆写新轮。保持成功 handoff 后正常 resume，不扩展 Desktop 多 branch 权威。

## 执行记录

- commit: `fc45b7eb` fix(hub-core): a failed first handoff turn releases its native id at the fatal event (R93)
- 反例先保留再修：基线实际运行 `--bin handoff_native` → exit 101，`retry marker count=1, retry native=Some("native-0"); expected None`，与本卡证据一致。
- 根因：失败 handoff 轮的 native id 要等 EOF 时 `restore_failed_handoff` 才清除；fatal→EOF 窗口内的重试在认领时读到 SessionStarted 留下的 `engine_session_id=Some(失败轮 id)` 且 `resume=true`，于是 resume 失败轮。等 EOF 后重试才得到 native=None——重试行为由尾流时序决定。
- 修复（与 EOF 后恢复同形，提前到 fatal 事件时刻）：`update_session` 的 fatal 分支在 `handoff_turn` 时同步清除 `engine_session_id`；banner/pending_handoff 仍按 R90 语义保留到成功。合成终态对改用本流自己观察到的 native id（任务内局部跟踪），事件投影不因会话表清除而变空。EOF 尾部恢复的 claim 校验照常——重试先认领时旧尾部被跳过，不覆写新轮。
- 验证：
  - 同一反例修复后重跑 → exit 0，`retry marker count=1, retry native=None`。
  - 新增 gate 覆盖两种时序，均比较完整 RuntimeRequest：
    - `retry_before_handoff_eof_does_not_resume_failed_native`（fatal 后流停在 EOF 前）：重试请求 `resume_session=None`、banner 恰好一次；新轮 Completed 后旧流释放，尾部不覆写（状态、native id、requests 数量全保持）。PASS。
    - `retry_after_failed_handoff_eof_resumes_no_native_identity`（SessionStarted→fatal→EOF，走合成终态路径）：合成 Completed 仍携带失败轮 native id（投影不变），会话表身份恢复 None，重试 `resume_session=None` + banner 一次。PASS。
