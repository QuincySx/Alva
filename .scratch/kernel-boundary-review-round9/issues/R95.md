# R95: Pi 的暂时性 assistant error 不应抢先截断原生重试

Priority: P1
Axis: Spec
Status: done (2026-09-19，commit c5e37703)
Origin: R82 / 多引擎适配器
Baseline: bae66d0f8aeebac36b4a57b84fa955489ae63f0d

## 责任范围与问题

crates/alva-engine-adapter-pi/src/mapping.rs:137–145,160–169；adapter.rs:153–181。

Pi 会先发 assistant error/message_end(error)，随后才发 agent_end(willRetry=true)、auto_retry_start 和成功结果。mapper 在前两个事件立即发 fatal，adapter 就停止读取，所以 R82 的 willRetry 分支来不及生效，CLI 的合法恢复被截断。时序依据本机 Pi 0.85.1 源码，详见 ADAPTERS-EXTRA.md。

## 证据

按原生顺序的独立真实 adapter fixture 实测 recoverable_retry_lost=true，只产生503 fatal + Completed(None)，后续重试成功答案丢失。

## 有限验收

保留暂时性错误状态直至可判定本轮是否重试，不凭单个 assistant错误立即锁定fatal；验证 error→agent_end(true)→retry→成功，答案保留且无fatal。同时验证重试耗尽/明确失败仍发唯一fatal+None、非重试错误可收敛、中途取消有界。增加真实顺序fixture，不只给agent_end(true)后直接成功的简化样本。

先保留反例再修实现，每个逻辑改动单独提交；记录真实命令、结果和 commit。遵守根/目录 AGENTS、分形协议；不回退其他人的修改。反例来自当前真实 API，但假引擎/CLI 不代表真实服务端端到端已验收。

  - `retry_exhausted_emits_one_fatal_and_no_result`：耗尽后 `auto_retry_end{success:false}` 恰好一个 fatal，`Completed{None}`。PASS。
