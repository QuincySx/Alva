## 责任范围与静态证据

`crates/alva-hub-core/src/runtime.rs:670–684,981–990,1225–1228`。

execute 注入 handoff banner 后立刻清除 pending_handoff；fatal Error 的投影把会话置为 Failed，使同 pid 新 execute 可认领。但 handoff 恢复只在旧流 EOF 后执行。若旧流 fatal 后还挂起，新轮会在 pending_handoff=false 下启动，丢失交接上下文；新 claim 还会使旧 EOF 的恢复被代际校验跳过。

## 有限验收

用受控 stream 固定：switch engine → 带唯一 handoff 标记的第一轮 → fatal Error → 在 EOF gate 未释放前尝试重跑 → 释放旧流。

- 可以在完整终态恢复之前拒绝重跑，或保证新轮拿到正确恢复后的上下文；不得允许无 handoff 上下文的重试。
- 重试请求包含原标记恰好一次；失败 native session 按既有契约处理，旧尾部不能覆写新轮。
- 同步启动 Err、fatal 后正常 EOF、缺 Completed、成功 handoff 不重复注入的已有回归保留。
- 只改 hub-core 的局部切换便利契约，不扩展成 Desktop 的多 branch 权威实现。
- 记录真实命令/结果与 commit；遵守目录 AGENTS。
