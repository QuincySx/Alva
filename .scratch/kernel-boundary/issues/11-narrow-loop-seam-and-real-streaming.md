# 11: 循环 seam 收窄，run 真流式

**What to build:** 可替换的循环 seam 目前有两个驱动签名——一个无界的历史签名，
一个有背压的新签名，外加一层把前者转发成后者的兼容适配器。
那层兼容是**为不存在的第三方实现付的成本**：全仓只有内核自带的默认实现和一个测试录制器。
删掉转发层，只留有背压的那一个。

同一片代码上还有一个货不对板：SDK 的运行入口宣称流式，实际**先把整轮跑完**，
期间所有事件堆在无界通道里，调用方既没法实时消费，事件多了还会吃内存。改成真流式。

**明确不做**：不要把这个 seam 细化成阶段级钩子（"决定下一步"、"决定怎么排这批工具"）。
那会把循环的内部结构变成公开契约，才是真正锁死内核演化的做法。
seam 保持"给你状态和配置，你还我事件流"这个粗粒度。理由写进 ADR-0007 的修订。
