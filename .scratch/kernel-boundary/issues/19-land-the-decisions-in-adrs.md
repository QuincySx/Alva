# 19: 决策落档

**What to build:** 把本次重构里**难以回退、未来读者会追问、且确实有过取舍**的决策写进 ADR，
并让仓库文档与新的架构一致。没有这一步，半年后这些边界会被当成技术债删掉——
四张零消费者的工具白名单就是前车之鉴。

四条：

1. **ADR-0008 内核与 agent 契约分层** —— 含对话记录与会话存储的拆分（同一个决策的两面）。
   记下那条判据：一个只会翻译文本的 agent 不需要的概念就不在内核里。
2. **ADR-0009 Tool 契约瘦身与策略外移** —— 二十个方法到七个；工具自述行为、harness 决定权限；
   以及为什么"工具可以拒绝自己"是个必须消除的隐患。
3. **ADR-0010 终端 agent 是内核的参考实现** —— CI 里那条"原生入口不得依赖引擎层"的规则，
   现在的理由写在脚本注释里，而且是个**已经过期的施工期理由**（避免合约变更同时打穿三端）。
   真实理由是：终端 agent 是内核唯一一个必须自己跑通的消费者，一旦它也改走引擎接口，
   内核就失去了唯一不能糊弄的用户。不写下来，早晚有人把这条规则当技术债删掉。
4. **修订 ADR-0007** —— 补一节说明循环 seam 为何保持整体粒度、为何明确拒绝阶段级钩子。
   这是对既有决策的收窄，不另起新 ADR。
