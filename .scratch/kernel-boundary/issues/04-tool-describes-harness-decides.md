# 04: 工具自述行为，harness 决定权限

**What to build:** 今天工具身上挂着一个"检查权限"的方法，它把**两件不同的事焊在一起**：
"允许还是询问还是拒绝"（决策）和"我拿这份入参会干什么"（描述）。

决策是 harness 的事——同一个工具在不同安全档下答案不同，工具无权替产品拍板。
更糟的是这个方法能返回"拒绝"，意味着**工具可以硬拒自己而 harness 无法覆盖**；
今天没爆只是因为除了它自己没人读这个返回值。

描述是工具的事——只有工具知道自己的入参长什么样。如果把描述也搬走，
harness 为了拼出一句人话就得知道某个具体工具有哪些字段，那是同样的耦合，只是方向反了。

所以：**拆开，不是移走。** 工具保留一个自述方法，说"我会干什么"，不含判断；
harness 的工具策略层给出允许 / 拒绝 / 询问，需要提示语时向工具索取那句话。

这是本组三张票里唯一有真实行为改动的一刀。
