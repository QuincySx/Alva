# 02: 清除内核契约层的死表面

**What to build:** 把内核契约层里**长期无人实现、也无人消费**的表面一次性清掉，
让"通用内核"这句话第一次名副其实。清除后，第三方实现一个工具时面对的是一份读得完的契约，
而不是二十个不知道该不该管的可选钩子。

三组：

1. **`Tool` 上的死方法** —— 描述搜索/读取性质、用户可见名、结果尺寸上限、是否延后、
   工具提示词、别名、是否启用，以及"是否破坏性"。前六个零重写零消费；
   "是否破坏性"更难看：派生宏会替五十个工具生成它，**没有一行代码读**。
2. **产品策略混进契约层** —— 四张按 agent 类型划分的工具白名单（零消费者），
   以及终端渲染帧率这类 UI 常量。
3. **七个模态契约** —— 图像 / 语音 / 视频 / 转录 / 审核 / 重排 / 嵌入，
   连同 provider 契约上对应的七个默认报错方法与注册表访问器。全仓零实现。
   将来真要做模态，它属于 provider 层，不属于 agent 循环的契约。
