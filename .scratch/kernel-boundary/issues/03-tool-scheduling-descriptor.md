# 03: 调度语义收成一个描述符

**What to build:** 工具现在用四个独立方法回答调度问题——能否与别的工具并行、会碰哪些资源、
按什么执行模式跑、是否自己管超时。这四件事永远一起被问、一起被用，拆成四个方法只是让每个
工具作者多面对三个钩子。合成**一个** `scheduling()`，返回一份调度描述符。

这是内核唯一需要向工具打听的额外信息（因为内核负责批量执行），所以它留在契约里；
但它必须是一个概念，不是四个。
