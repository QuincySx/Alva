# 18: 编排的决策与记账分家

**What to build:** Hub 是"多 agent 的 agent bot"，编排是它唯一的产品内核——
而现在编排**没有策略层**：策略就是持久化模块里那一千四百行 SQL 和状态机。
想换一种编排（纯流水线、投票式）就得改表结构。

这张票只做**纯机械的切分**：把"下一步该派谁做什么"的决策逻辑与
"已经发生了什么"的记账逻辑分成两块可分别阅读的代码，**行为零变化**。

**明确不抽接口。** 只有一种编排存在过，现在抽 trait 会抽错——
这个仓库已经在循环 seam 和那批死方法上犯过两次同样的错（凭想象留扩展点，
留了很久没有第二个实现者）。先让"哪些行是决策、哪些行是记账"变成肉眼可见的事实；
等第二种编排真要写时，接口的形状会自己浮出来。

**Blocked by:** 无（可立即开始）
