# UI07: 收紧输入区并梳理新会话、模型与上下文操作

**Priority:** P2
**Axis:** 用户最新 UI 重整需求 / 产品审查
**Origin:** 2026-09-11 用户“你好”真实会话及全 UI 反馈；HEAD `f9d0e57`
**Blocked by:** UI01、UI02、UI03
**Status:** ready-for-agent

## 问题与证据

“你好”截图的空输入区占据较大高度，权限/共享记录/模型和footer重复分行，底部显示长session目录名；新会话又以大工作方式卡片占据中央。发送与模型可用性、工作区前置状态分散。
这些高频操作应支持快速开始和继续对话，而不是要求用户理解底层session路径与多处配置。

## 实现范围

短输入时采用紧凑composer，随内容增长到有限高度；模型/引擎、权限、上下文和发送有稳定主次，低频共享/fallback设置收进合适入口。路径和路由完整ID放tooltip/详情。
新会话清楚呈现项目/独立会话的选择与结果，用可读名称反馈；选完后回到输入，不持续留下大引导块。模型菜单统一搜索、当前选择、不可用原因和真实runtime options，键盘可完成选择。
仅接入现有真实能力，不为新布局虚构附件或工具功能。

## 验收

- [ ] 空/短输入composer占用有明确上限，长输入可控增长且不遮挡最新回答。
- [ ] 工作区/模型未就绪时给出就近原因与可达操作，发送/停止状态明确。
- [ ] 模型选择、权限、上下文、发送/换行键盘路径完整；弹层与触发器对齐不遮住关键输入。
- [ ] 独立会话使用友好标签，不在常驻footer展示session UUID；详情可查看/复制真实路径。
- [ ] 默认与compact、窄窗口、中英文长模型名状态均不挤压变形。
