# UI01: 确定聊天优先的信息架构与视觉方向

**Priority:** P1
**Axis:** 用户最新 UI 重整需求 / 产品审查
**Origin:** 2026-09-11 用户“你好”真实会话及全 UI 反馈；HEAD `f9d0e57`
**Blocked by:** 无

## 问题与证据

用户 2026-09-11 在真实 Hub 发送“你好”后明确反馈：UI 不像常规 Agent、design tokens 与整体 UI 需要重整；执行时间线只属于检查器；Middleware 应二级展开/详情，不应大块占据首屏。
现有 web/src/AGENTS 第14条仍要求主聊天三泳道概览，与最新需求冲突。evidence/native/user-hello.png 是本轮验收起点，不能拿现有截图基线否决用户新要求。

## 实现范围

先固定各区域职责和视觉方向，供后续卡共享：聊天=用户问题/回答/紧凑工具进度/必要审批；Inspector=当前步骤、结果、异常和按需技术细节；Agent=协作关系；会话详情=设置/分支/记忆的次级面。
以成熟 Agent 的消息阅读流为主，减少仪表盘式卡片；暗色视觉先形成一套完整基准。提供“你好”、工具执行、失败、Inspector打开四种真实内容线框/样式样例，再落实到现有五层组件，不新建并行UI体系。
同步更新 UI glossary/wireframes/目录职责中冲突的时序与详情归属。用户本轮要求是新权威，不必再次请求是否可移动执行时间线。

## 验收

- [ ] 四个状态明确主次信息、入口、返回、滚动与宽度归属，评审者能看到具体样例。
- [ ] 主聊天没有执行泳道、完整UUID或Middleware清单；运行状态和审批仍就地可用。
- [ ] 检查器默认能回答当前做什么、完成/失败在哪里；高级信息按需进入。
- [ ] 既有规范与最新要求统一，后续卡不各自发明页面结构。
