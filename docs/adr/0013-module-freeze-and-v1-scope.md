# ADR 0013 模块固定、v1 范围与中间窗口

- Status: Accepted
- Date: 2026-11-07
- Amends: ADR 0012 的“桌面不使用 WebView”与“本次不批准任何抽象合并”两处

2026-11-07 对内核/SDK、Hub 产品层、UI 与设计稿差距做了全仓审查，并用 2 GiB 合成历史实测长会话。
用户据此决定：先固定模块和 interface，再对齐 UI。以下每项都经用户确认；落地顺序见 [ROADMAP](../ROADMAP.md)。

## 1. v1 范围

- 主线是会话、工具、权限、连接与工作区。伙伴、Team、自动化只固定 interface，界面排后。
- 产品只有终端 Agent 与 Hub；direct 桌面 `alva-desktop` 退役。
- 只验收 macOS；Windows 与 Linux 保持可编译，不承诺体验。
- Alva 引擎优先。Claude、Codex、Pi 保证对话、审批和消息流；富内容块先不支持，工具块只映射命令与改文件两类。

原因：目标是先把一个 Agent 做好。八个程序入口和大量外围能力分散了验收，主线反而没有闭环。

## 2. 自绘外壳，WebView 只用于 HTML 内容块

窗口外壳、消息列表、输入区和所有已知类型的内容块都用 MyGo 自绘。只有模型在运行时生成的 HTML/JS
才进入 WebView，并作为消息流里的一个块，不作为容器。判据是内容由谁写：编译进 Alva 的类型自绘，模型现场写的代码进沙箱。

HTML 块第一版：Untrusted 页面、临时会话、CSP 加内容规则断网，不能回调 Agent；同一时间只运行一个，其余显示截图。
先做数据块（模型只给数据，自绘图表与表格）；HTML 块要先通过 spike 验证滚动交接、高度回传、断网与内存，再进入生产。

否决：整个消息列表用一个 WebView。它常驻一个网页进程，原生组件进不了网页的文档流，文字的流畅度也交给了网页。
原因：外壳必须快且流畅，而多数对话根本不需要 WebView。

## 3. 中间窗口是内容块流

消息流的每一项都是带类型的内容块：用户消息、回复正文、工具活动、审批与问答、状态、数据块、HTML 块。
块由产品层从已提交历史投影出来，UI 只按类型渲染，不认工具名或引擎名。

工具活动的展示信息（类型、路径、命令、退出码、增删行数、结果引用）由各引擎 adapter 统一转换后进入 `engine.Event`。
原因：现有呈现靠 Role 字符串区分类型，Alva 的工具事件既不带参数也不带结果，无法展开或跳转。

## 4. 长会话是验收线

同一会话可能持续多天、历史达到 1–2 GB，打开、滚动和内存都不能随历史增长。在 2 GiB 数据上验收，初始预算：
打开会话 100 ms 内出首屏且能看到最近 20 条消息；滚动单帧 CPU p95 不超过 8 ms；中间窗口消息内存不超过 64 MiB。

为此：

- 流式增量约每 250 ms 合并写一行。回复的最终消息提交后，在同一事务里删除它的增量。增量是派生数据，
  完整正文仍在最终消息和原生记录中，所以不属于“不删除用户数据”保护的对象。
- 列表按消息分页加载，滚动时自动加载更早内容。
- 禁止全量读取会话，由架构测试把关。
- 长会话摘要压缩进入 v1，做成 Plugin。

原因：实测存储和列表引擎在 2 GiB 下不变慢，但按事件计数的 512 条窗口会让一条长回复挤掉整段对话；
超过 4096 条记录或 64 MiB 的全量读取直接报错，shell 恢复和 AEP 宿主都会调用它。

## 5. 内核与 SDK 收窄

- `Tool` 的必选方法只留名字、说明、参数 schema 和执行。调度与效果改为可选自述，缺省按串行、效果未知处理；
  删除 `IsReadOnly`，它可以从效果推出。工具可以自述效果，允许与否仍由策略决定。
- 上下文生命周期（七个钩子以及压缩、摘要、记忆等类型）移出内核到 `sdk/agent/context`，内核只保留 `ContextSource`。
- 一次 Run 内的模型、会话日志和工具集固定，删除运行中替换的 setter 及相应的重新绑定逻辑。
- SDK 目前没有外部用户或承诺，所以删除没有消费者的表面：`sdk/agent/graph`、`integration/protocol/acp`、
  `sdk/agent/analytics`、`extension/modelretry`、`sdk/agent/context/scope` 中未用的部分以及 agent ABI 里未用的导出。
  历史保留在 Git。只在本包内使用的导出改为非导出。
- 公开面快照补上 `harness`、`sdk/agent/context`、`sdk/agent/security` 与 `platform/host`，并分稳定与暂定两档。

这一节修订 ADR 0012 的“本次不批准任何抽象合并”。每项都按审查记录的职责、消费者、收益与损失经用户批准；
今后的合并或删除仍需同样说明。Graph 是被删除而不是被合并，“不把执行模型合成统一 runtime”的约束不变。
原因：这些表面没有生产消费者，或者让每个调用方背上实际用不到的约束。

## 6. Hub 产品 interface

- UI、HTTP 与 CLI 只通过产品服务访问 Hub，不直接调用 Store 或 Runtime，由架构测试把关。入口收敛为
  `Send`、带已观察执行身份的 `Stop`，以及统一的交互读取与回答。
- direct CLI 与 Hub 共用 harness 中一份纯值配置的 Agent 配方，可信工具列表由注册自动推导。
- 产品代码不比较引擎名，改为查询引擎能力声明。
- Hub 产品存储不承诺可换后端：业务规则就在 SQLite 事务里，窄接口只服务于消费者与测试。`platform/storage` 的可换性不变。

原因：desktop、server、CLI 直接调用 Store 和 Runtime，已经造成同一业务规则在不同入口表现不一致。

## 7. 设计资料

两个 `.smallpen` 包是设计正本，进入 Git。`docs/design/alva/exports/archive` 与 `source/intents` 是可再生的导出、
回执和一次性批次，约 540 MiB，留在本地并被忽略；指向它们的链接只在本地检出中可用。
原因：它们会永久撑大仓库历史，而以后需要时随时可以补进 Git，反过来清除则很难。

## 补充与取代（2026-11-09）

以下是对上文的补充，原文不改。

- **§1 工具块映射**：原文写外部引擎的工具块“只映射命令与改文件两类”。实际已映射六类：命令、读文件、改文件、搜索、子 Agent、待办（其余归入“其他工具”），见 `integration/engine/tool_display.go` 与 `integration/engine/process/tool_display.go`。
- **设置层级**：设置以应用级为主（M5）；会话可以覆盖，覆盖只影响下一新轮次；MCP 等需要批准的项按工作区记录批准，配置变更使对应批准失效。
- **图表说明的注入范围**：图表数据块的格式说明只对 Alva 和 Claude 注入。Codex 的开发者说明通道会替换用户自己的 `developer_instructions`，Pi 的 `--append-system-prompt` 会替换其 `APPEND_SYSTEM.md` 的发现，注入会破坏用户配置，所以这两个引擎暂不带说明（见 `integration/engine/process/adapter.go` 中 `ProductInstructions` 的注释）。
- **第一波业务规则决定（2026-11-08 起）**：
  - 审批被拒绝或被工作区边界拦下，这次结果作为工具结果交给模型，模型继续，本轮不因此失败；
  - 普通工具失败（文件不存在、路径或参数错误等）以错误结果交给模型，只有内部故障或用户取消才中止本轮；
  - Full 档下，工具自述为计费（Billable）的操作仍要询问，任何档位都一样；
  - Auto 档按效果判断：被工作区边界约束住的写入放行，其余询问，不看工具名；
  - 持久等待默认开启；
  - fallback 只在当前一轮生效，路由身份只含引擎、连接和模型。
