## 约束
Keep alva.smallpen's package id stable. Edit tokens.css, components/ (through source/build_next.py) and pages/ as files and run `smallpen check` after every edit. Required task/approval/error indicators cannot become hideable preferences. Do not claim that prototype settings, dynamic HTML or independent windows already execute.
The earlier JSON-format packages (alva-foundation.smallpen and the first alva.smallpen) were deleted on 2026-11-09; they are in git history at commit 690c4525. Work on alva.smallpen; its guide is [CLI-GUIDE.md](./CLI-GUIDE.md).
Before design or preview work, run `smallpen help skills --json`, read the returned available `smallpen-ui-design/SKILL.md`, then read [CLI-GUIDE.md](./CLI-GUIDE.md) and the relevant project SPECs. Do not copy the bundled Skill into this repository. Separate Tokens, content overrides, layout constraints and real component states; do not multiply every property into variants or treat fixed screenshot dimensions as responsive layout. Keep each rule's authoritative body once; visual specifications do not replace business SPECs. Verify one real component/composition before expanding the design system, and bind review evidence to the source revisions, selection and layout hash. Cross-platform implementation mapping does not change Alva's production stack.
Known and accepted (user decision 2026-11-09, aesthetics first): `smallpen check --render` reports about 29 `low_ui_contrast` notes for outline-only controls (Checkbox/Radio/Switch off states, avatars, disabled states). Do not change color Tokens (`controlBorder`, `border`) or component strokes to satisfy WCAG 1.4.11; see the contrast decision in DESIGN.md.
