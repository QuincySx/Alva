# Alva 路线图

模块固定与 v1 的落地顺序。决定与原因见 [ADR 0013](./adr/0013-module-freeze-and-v1-scope.md)，
实际进度与验收证据仍以根 [MIGRATION](../MIGRATION.md) 为准。顺序可以调整，调整时更新本页。

| 阶段 | 做什么 | 完成标准 |
|---|---|---|
| 0 保存现场 | 分批提交积压改动，跑全量测试作为基线 | 已完成（2026-11-07，`72d88b3b..38d75c50`） |
| 1 消息流 | 见下方三步 | 2 GiB 长会话验收门通过；图表与表格直接显示在消息里 |
| 2 内核收窄 | 收窄 `Tool`，上下文移出内核，Run 内状态固定，删除无消费者表面，补公开面快照，摘要压缩 Plugin，重写 CONTEXT 中失真的词条 | 长会话上下文连续；内核只剩必要机制 |
| 3 产品 interface | 封装 `HubService`，收敛 `Send`、`Stop` 与交互入口，统一配方，以能力查询替代引擎名，按会话加锁 | 架构测试禁止 desktop、server、CLI 直接调用 Store 或 Runtime |
| 4 拆 desktop | 按页的状态 module、统一的异步回执、补齐控件层 | 页面可以直接喂状态来渲染和测试 |
| 5 HTML 块 | 先 spike，再做 WebView 管理与沙箱 | 动效能显示，内存有上限，外发请求被拦截 |
| 6 对齐 UI | 先更新设计稿，再做 Tab、归档、两级导航与设置子页 | 按页对照验收 |

阶段 2 与阶段 3 改动的目录基本不重叠，可以并行；阶段 4 依赖阶段 3。

## 阶段 1：消息流

1. **数据与滚动**：流式增量合并、提交后删除已合并增量、产品层的内容块投影、按消息分页与滚动加载、清除全量读取调用方、长会话验收门。
2. **工具块**：统一的工具展示信息，以及下表的呈现与跳转。
3. **其余块**：审批与问答卡放进消息流，数据块（图表、表格）。

| 类型 | 折叠时一行 | 展开后 | 跳转 |
|---|---|---|---|
| 运行命令 | 命令、退出码 | 输出尾部 | 完整输出 |
| 读文件 | 路径 | 读到的片段 | 右栏打开文件 |
| 改文件 | 路径、增删行数 | diff | 右栏打开 diff |
| 搜索 | 关键词、命中数 | 结果列表 | 点结果打开文件 |
| 子 Agent | 任务、状态 | 结果摘要 | 进入子会话记录 |
| 其他工具 | 工具名、状态 | 结果文本 | 完整记录 |

长会话验收门在 2 GiB 数据上检查：打开会话 100 ms 内出首屏且能看到最近 20 条消息；滚动单帧 CPU p95 不超过 8 ms；
中间窗口消息内存不超过 64 MiB。另需覆盖长消息的流式重排与真实窗口下的帧率。

阶段 1 不包括按设计稿精修外观、Tab、归档、两级导航和设置页。
