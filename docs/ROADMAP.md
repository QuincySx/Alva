## 已定的产品决定

- 分叉从某条消息得到一个新会话并记下来源，不复用“分支”一词。
- 排队与插话都要：Enter 排在当前回复之后发送，⌘Enter 插进正在进行的回复。
- 保存点：Git 项目用隐藏引用为每轮建保存点，不在 Git 里的目录用现有的写入前备份。
- 第一轮只显示 token 与缓存命中，金额放到第二轮。
- 轨迹的“时长”按真实时间排布，“轮次、调用、子调用”切换分组粒度；实现中可按实际效果调整。
- 审批被拒绝或被工作区边界拦下：这次结果作为工具结果交给模型，模型继续往下走，本轮不因此失败。
- 普通工具失败（文件不存在、路径或参数错误等）以错误结果交给模型；只有内部故障或用户取消才中止本轮。
- 外部引擎的审批：Codex 和 Pi 默认改用 app-server / rpc 传输；Claude 使用 `--permission-prompt-tool` 接入审批卡。做完之前界面上明确标出“此引擎不会询问”。
- 同一个引擎内换模型时保留上下文：Alva 沿用同一个原生会话；外部引擎能续接就续接，不能再新建分支。
- fallback 只在当前一轮生效；路由身份是引擎、连接和模型。
- Full 档下，会产生计费的操作（hub_team 创建 Worker 等）仍然要询问；Auto 档按效果判断。
- 持久等待默认开启；开关计划模式不改权限档。
- 设置以应用级为主（M5 已实现），会话可以覆盖，批准按工作区记录。
- 伙伴不能使用 Full，每次伙伴发言都会重写权限档并关闭计划模式（保留这个限制）。
- Enter 发送、Shift+Enter 换行；删除采用软删除；分叉不复制历史；标题取首行；新工作区有待批准的 MCP 时，在输入框上方给出提示。
- `alva-desktop` 退役排进 M6。
- 内核收窄第二批（删除 `acp`、去掉 `IsReadOnly` 等）待用户批准。

## M1：对话呈现

1. **数据与滚动**：流式增量合并写入、最终消息提交后删除已合并增量、内容块投影移到产品层、按消息分页与滚动加载、
   清除全量读取调用方；内核为每个工具结果记录真实开始与结束时间；长会话验收门。
2. **轨迹**：输入、模型、工具三条泳道的时间轴，步骤列表，概述、预览与原始内容详情，搜索；`Inspector` 增加向前翻页。
3. **工具块**：统一的工具展示信息，以及下表的呈现与跳转；子 Agent 卡片；待办清单。
4. **其余块**：审批与问答卡进入对话，token 用量，数据块（图表、表格）。

| 类型 | 折叠时一行 | 展开后 | 跳转 |
|---|---|---|---|
| 运行命令 | 命令、退出码 | 输出尾部 | 完整输出 |
| 读文件 | 路径 | 读到的片段 | 右栏打开文件 |
| 改文件 | 路径、增删行数 | diff | 右栏打开 diff |
| 搜索 | 关键词、命中数 | 结果列表 | 点结果打开文件 |
| 子 Agent | 任务、状态 | 结果摘要 | 进入子会话记录 |
| 其他工具 | 工具名、状态 | 结果文本 | 完整记录 |

长会话验收门在 2 GiB 数据上检查：打开会话 100 ms 内出首屏且能看到最近 20 条消息；滚动单帧 CPU p95 不超过 8 ms；
中间窗口消息内存不超过 64 MiB。另需覆盖长消息的流式重排与真实窗口下的帧率。

M1 不包括按设计稿精修外观、Tab、归档、两级导航和设置页。
