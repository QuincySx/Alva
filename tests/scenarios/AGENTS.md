# Hub business scenarios
> 从产品入口端到端验证 v1 主线业务流程（会话、工具、权限、连接、工作区）。

## 地位
只含测试，不参与产品运行。走 `apps/hub/bootstrap` 的真实装配：真实 Alva 引擎、临时目录里的真实 SQLite 与真实工作区，
只把模型换成本地 httptest 假服务端；外部引擎用本包测试二进制自身充当假 CLI（print/exec JSONL 协议）。

## 逻辑
`model_test.go` 按真实协议（OpenAI 兼容 chat SSE、Anthropic Messages SSE）逐轮回放脚本并记录每个请求；
`hub_test.go` 打开/重开同一数据目录，只通过 HubService、Transcripts、Traces 与统一交互读取观察结果。
每个场景一个测试函数，名字描述用户行为，同时核对文件系统、消息流内容块和执行轨迹。
部分场景钉住的是当前已文档化、但待用户拍板的行为（拒绝审批或读不存在的文件会结束整轮），注释里写明。

## 约束
不读取用户真实数据目录、凭据或 CLI 配置；不联网；不改产品代码来迁就场景。
发现与 CONTEXT/ADR 或常识不符的行为时先写失败场景，再按影响面决定修复或交用户拍板。
崩溃场景只杀本包自己启动的子进程（`TestCrashHelperProcess`）。

## 业务域清单
| 文件 | 职责 |
|---|---|
| model_test.go | 可编排多轮的假模型服务端（两种协议、错误状态、悬停后继续或中断的流、模型目录、请求记录与工具结果提取） |
| hub_test.go | 真实装配夹具：开/关/重开、等待收尾、消息流块、轨迹步骤、历史与待处理交互 |
| connections_test.go | 新增 http/https 连接、读模型目录与探测、首条消息、错 key 鉴权失败与修复后无需重选、限流可重试、删除使用中的连接、改名/换Key/加请求头后照常发送、端点迁移被跟随并提示主机、同引擎换模型保留上下文 |
| workspace_test.go | 对话/项目模式各自的工作区、`../`/绝对路径/软链接越界全部拒绝、切换工作区后旧会话照常可用 |
| sessions_test.go | 新建/分页/搜索/重开后标题状态历史完全恢复并续接原生会话、两个会话并发不串话、双击发送只准入一轮 |
| turn_test.go | 流式部分可见/最终消息/增量清理/用量、中途停止保留已输出部分、提供者错误分型与审批过的 fallback、fallback只救当轮且被救回的失败显示灰色提示并在下一轮回到主路由、进程崩溃后恢复为 interrupted 并可继续 |
| tools_test.go | 模型经真实循环调用读/写/编辑/列目录/搜索/shell，文件系统、工具块、轨迹三者一致；可恢复工具错误；停止长命令；读不存在文件结束整轮（待拍板） |
| permissions_test.go | Ask/Auto/Full 下写文件与 shell、一次性同意不扩散、重复与迟到点击失败、拒绝无副作用且结束整轮（待拍板）、等待审批时停止、编造的工具名不弹审批 |
| questions_test.go | ask_human 直接回答、持久等待跨重启回答仍有效、放弃等待后可继续、未开持久等待时关闭应用结束该轮 |
| subagent_test.go | 子 Agent 结果以引用回到父模型、子 Agent 工具块与轨迹子会话跳转 |
| external_test.go | 同一会话 Alva→Codex→Claude→Pi→Alva 交接、外部工具块、重开后各引擎历史都在 |
